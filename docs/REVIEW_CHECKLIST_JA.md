# Born2beRoot 評価項目・日本語訳

ユーザーが提示した英語の評価票全文の日本語訳です。見出しの重複のみ整理しています。課題本文は [Born2beRoot.pdf](../Born2beRoot.pdf)（Version 5.2）、説明の準備は [REVIEW_GUIDE.md](REVIEW_GUIDE.md)、実演手順は [提出用README](../submit/README.md) を参照してください。以下は評価票の翻訳であり、実VMの合格状況を示すものではありません。

## はじめに（Introduction）

次のルールを守ってください。

- 評価の全過程を通じて、礼儀正しく、丁寧で、相手を尊重し、建設的に振る舞ってください。コミュニティの健全さはそれにかかっています。
- 評価対象の学生またはグループと一緒に、プロジェクトで起きている可能性のある不具合を見つけてください。見つかった問題について、時間を取って話し合い、議論してください。
- 課題の指示や機能の範囲について、仲間の理解が自分と異なる可能性を考慮してください。常に柔軟な姿勢を保ち、できる限り公正に採点してください。ピア評価が真剣に行われてこそ、教育として効果があります。

## 評価の指針（Guidelines）

- 評価対象の学生またはグループのGitリポジトリに提出された成果物だけを採点してください。
- Gitリポジトリが本人たちのものであることを再確認し、想定されたプロジェクトであることを確かめてください。また、空のフォルダで `git clone` が行われることを確認してください。
- 悪意のあるエイリアスによって、公式リポジトリの内容とは異なるものを評価させられないよう、注意深く確認してください。
- 想定外の事態を避けるため、採点を補助するスクリプト（テスト用・自動化用など）を使用する場合は、学生と一緒に内容を確認してください。
- 自分が評価対象の課題をまだ完了していない場合は、評価を始める前に課題文全体を読んでください。
- 空のリポジトリ、動作しないプログラム、Norm違反、不正行為などは、用意されているフラグで報告してください。その場合、評価は終了し、最終点は0点、不正行為の場合は-42点です。ただし不正行為以外では、同じ間違いを繰り返さないよう、提出物を一緒に振り返ることを強く推奨します。

添付資料：`subject.pdf`

## 事前確認（Preliminaries）

不正行為が疑われる場合は、ここで評価を中止してください。報告には「Cheat」フラグを使用します。冷静かつ慎重に判断し、このボタンの使用には十分注意してください。

### 事前テスト（Preliminary tests）

- 評価対象の学生またはグループがその場にいる場合に限り、口頭試問を実施できます。知識を共有することで、全員が学べるようにするためです。
- 提出物がない場合、またはファイル・ディレクトリ・ファイル名が誤っている場合は0点とし、評価を終了してください。
- このプロジェクトでは、学生の端末上で、その学生のGitリポジトリをクローンしてください。

## 全般的な確認（General instructions）

評価中に確認を手伝ってもらう必要がある場合、評価対象の学生は評価者を補助しなければなりません。

1. クローンしたリポジトリのルートに `signature.txt` があることを確認してください。
2. `signature.txt` 内の署名と、拡張子 `.vdi` の仮想マシンディスクファイルの署名が一致することを確認してください。単純な `diff` で2つの署名を比較できます。必要なら、`.vdi` の場所を学生に尋ねてください。
3. `.vdi` はVirtualBoxの仮想ディスクの拡張子です。UTMなど別の仮想化ソフトウェアを使っている場合、拡張子は異なります。
4. スナップショットが存在しないことを確認してください。多くの仮想化ソフトウェアにこの機能があります。
5. VMを起動する前にコールドスナップショットを作り評価終了時に削除するか、仮想ディスクを別ディレクトリへ複製してそのコピーから起動してください。どちらの方法でも、以後の評価に向けて元の `.vdi` を変更せず、署名を同一に保つ必要があります。
6. 評価開始前から動いているVMは受け入れないでください。
7. 評価するVMを起動してください。

期待どおりに動作しない場合、または署名が一致しない場合は、ここで評価を終了してください。

## 必須項目（Mandatory part）

### README.mdの確認

- リポジトリのルートに `README.md` があることを確認してください。
- 最初の行は、斜体で `This project has been created as part of the 42 curriculum by <login...>` という指定形式になっている必要があります。
- 少なくとも、プロジェクトの説明、OSの選択（DebianまたはRockyの長所・短所）、主な設計上の選択（パーティション構成、セキュリティポリシー、ユーザー管理、サービス）が含まれていることを確認してください。
- 次の比較も必要です：DebianとRocky Linux、AppArmorとSELinux、UFWとfirewalld、VirtualBoxとUTM。

どれかが欠けている場合は、ここで評価を終了してください。

### プロジェクト概要（Project overview）

学生は次の内容を簡潔に説明できなければなりません。

- 仮想マシンの仕組み。
- 選んだOSとその理由。
- RockyとDebianの基本的な違い。
- 仮想マシンの用途。
- Rockyを選んだ場合：SELinuxとDNFとは何か。
- Debianを選んだ場合：aptitudeとaptの違い、およびAppArmorとは何か。

評価中、スクリプトが10分ごとに情報を表示しなければなりません。詳細な動作確認は後で行います。説明が明確でない場合は、ここで評価を終了してください。

### 基本設定（Simple setup）

確認に補助が必要な場合は、学生が手伝えることを忘れないでください。

- 起動時にグラフィカル環境がないことを確認してください。
- このマシンに接続する前にパスワードが要求される必要があります。
- 学生の補助を受け、rootではないユーザーでログインしてください。
- 選んだパスワードが課題の規則を満たしているか注意してください。
- 学生の補助を受け、UFWサービスが起動していることを確認してください。
- 同様に、SSHサービスが起動していることを確認してください。
- 選んだOSがDebianまたはRockyであることを確認してください。

期待どおりに動作しない項目、または説明が不明確な項目があれば、ここで評価を終了してください。

### ユーザー・手順1（User step 1）

確認に補助が必要な場合は、学生が手伝える必要があります。

- 学生のログイン名と同じ名前のユーザーがVMに存在することが課題で求められています。
- そのユーザーが存在し、`sudo` と `user42` グループに所属することを確認してください。
- 次の手順で、課題のパスワードポリシーが実装されていることを確認してください。

まず、新しいユーザーを作成します。課題のルールを満たす、評価者が選んだパスワードを設定してください。次に学生は、要求されたルールをVM上でどのように設定したか説明しなければなりません。通常、変更するファイルは1つか2つです。問題があれば、ここで評価を終了してください。

### ユーザー・手順2（User step 2）

新規ユーザーができたら、目の前で `evaluating` というグループを作り、そのユーザーを所属させるよう学生に依頼してください。最後に所属を確認してください。

続いて、このパスワードポリシーの利点と、その導入の長所・短所を説明してもらってください。「課題で要求されているから」という回答では不十分です。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

### ホスト名とパーティション（Hostname and partitions）

確認に補助が必要な場合は、学生が手伝える必要があります。

- ホスト名が、学生のログイン名に `42` を付けた `login42` 形式であることを確認してください。
- ログイン名の部分を評価者のログイン名に置き換え、再起動してください。再起動後に変更が反映されていなければ、ここで評価を終了してください。その後、元のホスト名に戻して構いません。
- このVMのパーティションを表示する方法を学生に尋ねてください。
- 表示を課題文の例と比較してください。ボーナスに取り組んでいる場合は、ボーナス用の例を参照します。
- この部分は、得点について話し合う機会です。
- 学生は、LVMとは何か、どう動作するかを簡潔に説明できなければなりません。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

### SUDO

確認に補助が必要な場合は、学生が手伝える必要があります。

1. VMに `sudo` が正しくインストールされていることを確認してください。
2. 学生に、新規ユーザーを `sudo` グループに追加する操作を実演してもらってください。
3. 学生は、自分で選んだ例を使ってsudoの役割と動作を説明し、続いて課題が要求する厳密なルールの実装を示さなければなりません。
4. `/var/log/sudo/` ディレクトリが存在し、少なくとも1つのファイルがあることを確認してください。
5. ファイルの内容を確認してください。sudoで実行したコマンドの履歴が見える必要があります。
6. sudoでコマンドを実行し、同ディレクトリ内のファイルが更新されたことを確認してください。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

### UFW / Firewalld

確認に補助が必要な場合は、学生が手伝える必要があります。

- UFW（Rockyの場合はFirewalld）がVMに正しくインストールされ、正常に動作していることを確認してください。
- 学生は、UFWまたはFirewalldとは何か、なぜ使うのかを基本的な言葉で説明できなければなりません。
- 有効なルールを一覧表示してください。4242番ポートのルールが必要です。
- 8080番ポートを開く新しいルールを追加し、有効なルール一覧で追加を確認してください。
- 最後に、学生の補助を受け、その新しいルールを削除してください。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

### SSH

確認に補助が必要な場合は、学生が手伝える必要があります。

- SSHサービスがVMに正しくインストールされ、正常に動作していることを確認してください。
- 学生はSSHとは何か、使う利点は何かを基本的な言葉で説明できなければなりません。
- VM内のSSHサービスが4242番ポートだけを使っていることを確認してください。
- 学生の補助を受け、新しく作ったユーザーでSSHログインしてください。鍵とパスワードのどちらを使うかは学生の構成によります。
- 課題に従い、`root` ユーザーではSSH接続できないことも確認してください。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

### 監視スクリプト（Script monitoring）

確認に補助が必要な場合は、学生が手伝える必要があります。学生は次を簡潔に説明しなければなりません。

- コードを見せながら、スクリプトがどう動くか。
- `cron` とは何か。
- サーバー起動時から10分ごとに動かすため、どのように設定したか。

正しく動作することを確認したら、学生に毎分実行する設定へ変更してもらってください。動的な値が正しく表示されるか確かめるため、必要なコマンドを自由に実行して構いません。

最後に、スクリプトそのものを変更せず、サーバー起動後にスクリプトが実行されないようにしてもらってください。確認のため、もう一度サーバーを再起動します。起動後、スクリプトが同じ場所に存在し、権限が変わっておらず、内容も変更されていないことを確認してください。

期待どおりに動作しない、または説明が不明確な場合は、ここで評価を終了してください。

## ボーナス（Bonus）

必須項目がすべて完全に完了し、想定外・不適切な使用に対するエラー処理もできている場合に限り、ボーナスを評価してください。口頭試問で必須項目のすべてに合格していなければ、ボーナス点は一切考慮しません。

課題文と学生の補助を使って、認められているボーナスを確認してください。

- パーティション構成：2点。
- 課題指定のサービスだけを使ったWordPressの構築：2点。
- 自由選択のサービス：1点。

追加した各サービスが正しく実装され、動作することを確認・テストしてください。自由選択のサービスについて、学生は仕組みと有用だと考える理由を簡潔に説明する必要があります。NGINXとApache2は禁止です。

0（失敗）から5（優秀）で採点してください。
